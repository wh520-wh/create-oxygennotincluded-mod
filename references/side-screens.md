# 建筑侧屏交互

适用于建筑自定义对象选择、配置、文本输入和执行按钮；修改原生任务页签的内容另见[任务面板与受阻原因](chores-panel-and-reasons.md)。

来源：Execution Platform 0.1.0、U59-744825-SCRPN。原生类型与初始化路径已核对，项目编译通过；自建侧屏的加载、输入、布局和清理尚未游戏实测。下面给出判断要点，不将项目模板当作已验证可直接复制的组件。

## 原生组件不只是看起来相同

先查相近原版侧屏的注册、`IsValidForTarget`、`SetTarget`、`ClearTarget` 和清理生命周期，保留其选择焦点与输入习惯。私有字段或反射注册只按目标版本使用，核对字段缺失时的失败反馈，避免每次打开面板都重复注册。

`LocText` 是 `TextMeshProUGUI` 子类，不是 `UnityEngine.UI.Text`。复用当前游戏的字体、材质和样式，确保汉字显示；仅引用 TextRenderingModule 并不能替代 TMP 组件。程序集引用以实际使用类型为准。

U59 `LocText.Awake` 会处理非空本地化 key、Localization 修正、事件订阅以及样式；`allowOverride == false` 时会应用样式设置。活动对象上 `AddComponent` 后才配置字段，可能已经晚于 Awake。可用经过核对的模板或先构建未激活对象，设置 key、样式及字体后再激活；不要把模板继承来的旧 key 留在动态标签上。

文本框优先接入原生 `KInputField`/`KInputTextField` 路径，核对克隆模板的回调、导航关系和父级依赖。输入期间要让游戏快捷键正确被消费，不能输入字母时同时触发建造、暂停等操作，也不能关闭面板后继续吞键。

## UI 展示与行为授权分开

配置和操作状态放在建筑组件，不由侧屏生命周期拥有。切换选中对象后重新绑定，按钮回调不能保留上个目标；关闭 UI 不等于取消正在运行的建筑任务。

选择列表明确过滤存活、世界和可操作性；同名小人使用稳定身份，不以显示名作查找键。后台状态变化时仍需校验，尤其是目标死亡、离场、建筑失效及重复点击。

不可逆操作在后端检查真实条件并进入锁定阶段；前端按钮只提供准确反馈。任务进行中哪些配置允许修改由设计决定，避免“UI 改了罪名/配方，实际操作还是旧值”。相关状态与存档见[复制人任务与效果](duplicants-chores-and-effects.md)。

## 刷新不能破坏输入

状态变化及时更新，稳定内容可缓存或节流；不要每帧销毁重建所有控件。对象列表正在展开或文本正在编辑时，避免刷新覆盖选中项、关闭列表或把光标移回开头。目标改变与有效性丧失可立即处理，不等于对所有内容高频重建。

自定义文本明确去首尾空白、空值回退、长度上限和富文本处理；输入框与标签分别核对。文件、类名和内部 ID 可以英文，玩家可见字符串通过本地化键维护中文及英文默认值；不要将内部 ID 直接显示给玩家。

标签和 tooltip 准确区分“立即增加百分点”“每周期变化率”“剩余周期”。按钮按实际命令命名，状态说明告诉玩家当前为什么不可操作，不用实现术语或编号代替。

## 清理与实际显示

`ClearTarget` 与 `OnCleanUp` 处理订阅、回调及目标引用；常驻模板与临时面板的销毁边界分清。事件处理器注册一次、解除一次，不让旧面板继续刷新。

侧屏至少在相关的实际场景检查：中文字体、常见 UI 缩放、切换建筑、目标消失、输入与快捷键、列表展开时刷新、关闭重开和读档。运行中长文本不能挤出按钮或遮挡邻近状态；编译与静态层级检查不能证明这些表现。
