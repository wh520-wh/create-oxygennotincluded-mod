# 已发生的故障与定位方法

这些案例来自 WHHW_7A5C 重水 Mod，供推导检查方法，不把它的数值、标签或补丁机械套用到别的 Mod。

## 元素名称被再次哈希

旧实现误把稳定哈希的数字字符串当 elementId。重蒸汽规范名称 WHHW_7A5C_HeavySteam 的哈希为 -231445647，而字符串 "-231445647" 再哈希得到 -339679289；实际日志正好出现后者。Element 表使用再次哈希值，Substance 表使用预期值，渲染器找不到材质。

处理：统一字符串名称、稳定哈希、Substance 身份、存储 Tag；只对自己的 Entry 在正确生命周期设置相变目标。验证最终元素与物质查找，而不是只打印“已添加材质”。不要先用全局 Enum Patch 遮掩不一致。

## 材质创建太早

加载 Prefix 中原版 Substance.material 可为 null；直接 new Material(source.material) 造成崩溃。寻找目标加载阶段实际可用的模板，再核对原版最终 shader/texture hookup；自身独立材质最终绑定不得修改原版共享材料。补材质并不能修正身份错位，两类原因分别验证。

## 动画目录重复后缀

资源加载器自动追加 _kanim，目录本身也带后缀就注册成 _kanim_kanim。代码查找失败或使用占位资源。按实际注册名检查 Assets.Anims，包内资源命名和代码必须一致。

## 液体存在但没有瓶子

只加 Element/Substance 没加可搬运实体，导致装桶列表、擦拭成瓶和运输链不完整。补适用 IOreConfig/原生实体模板及完整容器动画；验证环境→物品→搬运→释放→环境的循环。重冰碎块、重蒸汽罐要独立判定，不能默认自动生成。

## ui 状态存在但图标是问号

动画 bank 的 ui 与 build symbol 的 ui 不是同一层。若图集里所有 symbol 都改为前缀部件名，默认 UI 查找仍可能找不到需要的符号。核对实际 GetUISprite 消费路径、帧与 symbol，补正确图标，不通过大范围 UI 补丁掩盖资源结构。

## 画布比例看似正确但建筑悬空

600×400 画布并不等于可见机器刚好占 6×4。旧图形有大量上下透明留白，单位换算和原点未在游戏格子上验证。检查非透明包围盒、底座基线、控制器 scale、矩阵、奇偶宽度及整个动画循环。不要仅整张放大缩小，更不要把建筑变实心砖。

## 发电却不是发电厂里的发电建筑

旧代码只有 IndustrialMachinery，漏 PowerBuilding 等适用分类。Generator 和 Tinkerable 存在不意味着房间标签正确。对照原版同类补齐分类，测试房间→电控站→芯片→小人调优→实际功率增益。不要把反应器标发电设备或改房间规则来凑通过。

## 程序画图完成但精细程度不足

规整线条、重复圆角盒子、少量螺丝和大面积平涂呈现示意图质感。提高分辨率仍不能得到原版手绘层次。按美术参考的结构、材料、线条和光向多轮精修，在原版同场截图和缩略图验收。

## 证据不足却过早承诺

编译和资源解析通过后宣称“支持完整调优”或“已修好”，可能漏掉原生导航、房间和存档。明确区分证据层级，以完整场景结果结案。重复修同类 bug 时追问“首次错误与根因究竟是什么”，不要反复补表面异常。

## 图标不再问号，却巨大并遮挡菜单

补上 ui 动画与 ui 符号后图标能被找到，但把整台建筑的图像尺寸与几何直接用于菜单图，菜单里图标巨大、盖住邻近条目。仅缩小 PNG 无效——显示大小由图集 UV、符号几何、ANIM 边界与变换矩阵共同决定。处理：菜单图独立设置图像尺寸、符号尺寸、动画边界与偏移；图片、UV、几何、边界、偏移同步核对；按建造菜单、研究、选择面板等入口分别验收。能查找、尺寸合适、居中、不遮挡、各缩放可读全部满足才算通过。

## 只修截图里的那一个对象

发电机图标错误修复后，反应器与三个元素图标仍带同样问题——它们由同一套资源生成代码产出。处理：追查共用生成器，检查全部同流程对象；修复范围由共同原因决定，不由用户截图里出现的对象决定。修复后与旧包比较不应受影响的内容（本次教训：全部非 ui 动画逐字节相同、DLL 相同），证明建筑本体没有被连带改坏。

## 参考 Mod 的 BottleFlipper 被当成原版组件

参考项目中的 BottleFlipper 是那个 Mod 自己实现的特殊组件，不是原版装瓶必需机制；照名字搬用会把参考 Mod 的独有机制当成原版通用需求。处理：引用参考实现的组件前先追查来源、用途与依赖，判断它解决的是原版通用需求还是参考项目独有机制；装瓶链仍按目标版本原生路径核对。

## 动画状态齐全但蓝图是成品外观

补齐 place、construction 状态名后直接复用成品建筑图层：资源结构完整，放置时却显示完整填色、金属阴影和运行部件，没有原版蓝图线稿效果。处理：对照原版建筑确认放置预览、待建、施工、完成分别使用什么动画、符号和渲染机制；线稿预览单独制作，不用成品图降透明度冒充；预览着色与可放置提示的来源（游戏控制还是资源提供）分别核对；蓝图、施工、成品保持占地、原点、缩放、管口与地板基线一致，建造前后不跳位；运行灯光、液面、调优标记只在应出现的阶段显示。仅状态名存在或资源解析通过不能判定完成。

## 调优标记存在但增益没有接通

添加 Tinkerable、显示调优标记或出现“工程师的调校”状态，都可能只是界面层存在，实际发电仍读固定基础功率；也可能在原生机制已计算增益后再次乘倍数，造成重复加成。不能凭固定效果栏没有变化就认定调优失效，也不能凭标记出现就认定已接通。处理：按完整流程逐环节验证——房间、电控站、芯片、工程师到达、完成调优、效果添加、发电属性变化、实际产电变化、效果到期、存档读回；实际发电使用原生增益作用后的属性；保持供料与运行条件一致，比较相同实际运行时间内累计产电量与燃料消耗。未实测前标“调优实际增益待验证”。

## 元素与图标齐全但材料没有完整外观

新冰类材料注册了 Element/Substance、菜单也有图标，但环境格子外观、挖掘碎块、储存形态分属不同显示链：碎块实体未生成，或生成了却因动画状态、透明度、尺寸或位置问题不可见。原生固体实体模板按质量请求 idle1、idle2、idle3 等状态，自制资源只提供 idle 时外观缺失。处理：菜单图标、格子外观、碎块/掉落物、储存形态分别实现和验收；核对原生模板实际请求的状态名与数量（以目标版本同类对象为准，不机械套用）；碎块用合适图元、缩放、原点，不继承建筑地板偏移；区分“未生成”与“不可见”，分别查 Prefab、元素身份、动画状态、透明度、尺寸和位置。
