# 验证、兼容与交付

## 证据层级

| 证据 | 能证明 | 不能替代 |
| --- | --- | --- |
| 源码与程序集检查 | 方法/字段/类型存在，设计与调用路径 | 原生方法真实运行、模拟器行为 |
| 编译通过 | 语法与引用类型基本兼容 | 加载顺序、资源、房间、读档 |
| 单元或替身回归 | 隔离逻辑与历史 bug 条件 | 原生电网/液体/导航和实际游戏 |
| 资源结构检查 | 文件格式、索引、UV、状态、有限数值 | shader 效果、格子尺度、UI 消费路径、图标尺寸与布局 |
| 游戏新沙盒 | 目标版的加载和交互 | 老存档迁移、所有 DLC 和 Mod 共存 |
| 保存读取/升级与共存 | 被测试组合和迁移路径 | 未测试版本/组合的全面保证 |

在项目审查表使用每种证据的真实路径、版本及结果。禁止把“尚未在游戏中执行的运行期断言”列为已经通过。结案结论限定到实际检查范围：只做了资源检查就写“资源检查通过，游戏显示待确认”，不写“已修复”。

## 必须执行的场景

- 启动/启用/重启/进入新世界：完整首次 Player.log，资源和 Prefab 查找结果。
- 正常功能：输入可获得、玩家可选、小人可达、处理结果与 UI 一致。
- 环境和失败：错料、空库存、输入/输出断开堵塞、停电、红信号、过热、淹没与解除故障。
- 生命周期：暂停/恢复、倍速、拆除返还、销毁、存档退出重进、跨世界（适用）、版本升级。
- 数值：实际质量、功率/能量、温度/病菌、属性/调优与时间单位；调优验收保持供料、出料与运行条件一致，比较调优前后相同实际运行时间内的累计产电量与燃料消耗。
- 美术：原版同场、地板/格子、缩略图、工作循环、翻转、容器/掉落物、互动动作、各显示入口（建造菜单/研究/选择面板）图标的尺寸、居中与遮挡、建造阶段（放置预览/无效位置/待建/施工/完成）与同类原版并排比较。
- 界面与卡片：新增建筑的悬浮卡片、选中面板、效果栏、电路列表与覆盖层逐项核对；固定说明与动态数值分别验证来源，确认动态值随运行状态变化。
- 原版行为：至少测试一个相邻原版对象仍正常；范围性补丁要测试非目标与另一个自定义对象。

按风险增加有意义测试，不为小的可逆美术改动写照抄实现的单元测试。重要身份/注册修复保留能复现旧 bug 的回归。功能不完整时继续实现；只有工具/环境阻碍才明确留待实测，别为节省工作停在概念方案。

## 崩溃定位

读取完整日志的首次异常及其前置 Mod 日志，记录 game build、程序集、启用列表和截图。后续重复渲染 NRE 可能只是首次错误的连锁结果，不逐个修表象。

一次建立一个可证伪根因，写出预期正确值和日志实际值。先核对 ID、标签、加载名、生命周期、null 模板和资源索引，再作局部修改。新版日志写清版本与关键注册结果；控制频率，避免每 tick 反复打印引发错误风暴。不要把 Debug.LogError 改成 Warning 当作根因修复。

## 修复验证与差量回归

修复共用资源生成器或图标后，与旧包逐项比较本次不应受影响的内容：非 ui 动画逐字节相同、DLL 相同（本次教训：菜单修好了，仍要与旧包比较证明建筑动画没被连带缩小、偏移或变化）。菜单正常不等于建筑本体没被改坏。

检查规则要针对真实失败原因（图标几何、UV、边界、偏移），并用已知错误资源自测：检查必须能在旧的错误资源上失败，避免写出永远通过的检查。原来的检查能发现缺少 ui 符号，却没有拦住 ui 使用整台建筑尺寸——新增检查要对准这次真实的失败原因。

结论限定到实际检查范围：资源结构与差量比较通过只写“资源检查通过，游戏显示待确认”。用户截图提供的实际失败证据要回写成新的检查规则；文件解析通过不能代替游戏内最终验收。

## 兼容与性能

使用唯一稳定命名空间、建筑/元素/配方/标签/资源/日志前缀；通用 KAnim symbol 遵守消费者约定。精确选目标方法和对象，只追加自己的菜单研究，保留原方法。避免不必要 Transpiler、全局 Enum Patch、共享原版材质修改及全表重建。

最小依赖，声明真实版本；不要捆绑游戏 DLL 或第二套 Harmony。查 DLC 条件、可选 Mod 检测与失败回退。对原生加载必须成功的步骤尽早验证并给诊断，不承诺原生模拟器注册失败可完全隔离。

核对模拟 tick、暂停/倍速、事件订阅/清理、每帧分配、对象搜索缓存、许多设备同时运行与性能日志。不要在每台建筑的每帧全局扫描全部元素或建筑。

## 保存和升级

稳定 ID 是保存契约。修改旧 ID/Tag 先调查用户存档里的实际身份，设计版本迁移或明确新沙盒限制。不要因为清理名称就静默改掉所有稳定 ID。检查字段序列化和加载时重建，检查 Storage 库存、运行状态、调优 buff、动画和事件重新绑定。

含自定义内容的存档可能依赖 Mod，卸载不等于安全读取。交付前明确说明备份、升级、回滚与已验证迁移；安装脚本备份 Mod 不等于备份存档。未经授权不修改用户重要存档。

## 安装包与报告

提供正确入口与元数据、目标 API/build、独立 DLL、实际资源、中文说明、完整源码、可编辑美术和许可来源。排除游戏 DLL、缓存、调试日志、用户存档、密钥和旧版本并行加载。

核对压缩包目录套层、资源名字与版本标记。纯美术修复允许资源包版本与 DLL 版本不同步（本次教训：v0.2.1 资源修复包 DLL 仍显示 v0.2.0），安装说明必须明确解释哪部分更新、哪部分没变，避免用户以为升级失败；资源修复必须完整安装动画文件并重启游戏，只替换 DLL 不能生效。安装到用户实际 Mod 路径，不要求替换游戏 DLL；关闭游戏、备份自身旧 Mod、避免破坏其他 Mod。重编译失败时不能安装旧 DLL 冒充成功。

最终报告先说明可用结果，再列适用的待验证项和重大限制。不要说“彻底修好”“完全无冲突”或“正式验收通过”，除非有足够证据且限定具体测试范围。
