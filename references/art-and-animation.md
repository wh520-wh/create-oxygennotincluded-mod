# 原版风格美术与动画经验

## 外形与精细程度

遵循主文件中用户选择的美术合作方式。用户明确要求原型时，可以先做简化方案；成熟交付应精修至与原版工业建筑同场协调，不能把占位图当最终美术。

《缺氧》是手绘工业卡通，不只是低分辨率像素画。参考相近原版对象的轮廓、色板、线宽、光向和细节密度；避免纯几何示意图、光滑写实3D、高饱和塑料感，以及整齐重复的圆角盒子。保留用户认可的外形，不擅自换成另一台机器。

先让结构可信：底座、承重、管线、传动、控制和检修部分有合理关系。再用变化的深色外轮廓、较细内部线、统一明暗、接缝、边缘高光和少量磨损增加层次。玻璃有厚度和反光，液面按设计保持合理方向。别只放大图片或添加随机螺丝就认为精细了。

看常用缩放下的识别度，也看放大边缘和与原版并排的协调程度。概念图只是输入，还要加工为实际可用的透明图元、动画和图集。保留可编辑源文件、轴心和生成参数，不重新分发原版游戏美术。

## KAnim 的常见遗漏

- 区分动画状态与 build symbol。存在 ui 动画不代表 UI 能找到所需 ui 符号；通用符号遵循消费者约定，不盲目全部改名前缀。
- 按目标版本和原版同类对象确认实际使用的状态、帧、符号覆盖及质量分档。建筑、瓶罐、碎块不能共享一套臆造的状态名。
- 核对目录、资源注册键、atlas、build.bytes 和 anim.bytes。加载器若追加 _kanim，目录不要再带一次后缀。
- 自制写入器注意版本、索引、UV、排序、矩阵、边界、帧率和图集留边。文件能解析不代表游戏显示正确。
- 工作、停机和故障外观要反映状态；活动部件围绕实际机械轴心运动，避免整台机器绕画布中心摇摆。
- 原生声音可以运行时引用或按自己的动画链接，核对播放与停止，不随意复制原版文件或全局改声音表。

## 占地与位置

画布尺寸、可见轮廓、动画边界和 BuildingDef 占地是不同概念。检查 KAnim 单位、controller scale、符号几何和变换共同形成的结果，不能认定每100像素必然是一格。

底座应贴合地板，注意奇偶宽度的整格/半格原点；主体和镂空合理对应占地，透明留白不能充当机器高度。非实心建筑的占地格子仍可能含空气，不要为视觉对齐把它改成实心砖。

看整个工作循环，活动部件不能穿墙或穿过相邻机器；核对端口、自动化口、翻转、小人工作位置及叠层遮挡。格子对照图有助于校准，最终位置仍看游戏表现。

## 图标是独立显示入口

图标能显示之后，还要看尺寸、居中、辨识度和是否遮挡邻近条目。建造菜单、研究、选中面板和物品列表可能取不同资源，按适用入口检查。

菜单图独立处理图像尺寸、符号几何、UV、动画边界和偏移，不能继承建筑的地板位移。只缩小PNG可能仍然巨大。128×128是某次项目方案，不是所有Mod的硬性标准。

若生成器被多个对象共用，检查同流程对象；修图标时也留意建筑本体和其他入口有没有受影响。

## 建造阶段

分别考虑鼠标放置预览、待建蓝图、施工和成品。只添加 place/construction 名称、却复用成品图层，会显示完整填色和运行部件。

对照原版确认各阶段的动画、符号和渲染方式。需要线稿预览时单独制作外轮廓和必要结构线，不拿成品图降低透明度冒充；核对颜色、透明度和无效位置提示由谁控制，避免重复着色。施工与待建不默认相同。

这些阶段共享准确的占地、原点、缩放和地板基线，完成建造不跳位；液面、运行灯和调优标记只出现在合适阶段。

## 适量的视觉检查

按本次任务看原版同场、常用缩放、占地、图标和主要状态；涉及掉落物时看实际瓶罐/碎块。不要为局部修图强制重做全部美术。没有游戏截图时只说明资源检查结果，保留实际显示待确认。
