# 原版风格美术与动画经验

## 外形与精细程度

遵循主文件中用户选择的美术合作方式。用户明确要求原型时，可以先做简化方案；成熟交付应精修至与原版工业建筑同场协调，不能把占位图当最终美术。

《缺氧》是手绘工业卡通，不只是低分辨率像素画。参考相近原版对象的轮廓、色板、线宽、光向和细节密度；避免纯几何示意图、光滑写实3D、高饱和塑料感，以及整齐重复的圆角盒子。保留用户认可的外形，不擅自换成另一台机器。

先让结构可信：底座、承重、管线、传动、控制和检修部分有合理关系。再用变化的深色外轮廓、较细内部线、统一明暗、接缝、边缘高光和少量磨损增加层次。玻璃有厚度和反光，液面按设计保持合理方向。别只放大图片或添加随机螺丝就认为精细了。

看常用缩放下的识别度，也看放大边缘和与原版并排的协调程度。概念图只是输入，还要加工为实际可用的透明图元、动画和图集。保留可编辑源文件、轴心和生成参数，不重新分发原版游戏美术。

## KAnim 的常见遗漏

- 区分动画状态与 build symbol。存在 ui 动画不代表 UI 能找到所需 ui 符号；通用符号遵循消费者约定，不盲目全部改名前缀。
- 按目标版本和原版同类对象确认实际使用的状态、帧、符号覆盖及质量分档。建筑、瓶罐、碎块不能共享一套臆造的状态名。
- 核对目录、资源注册键、atlas、build.bytes 和 anim.bytes。加载器若追加 _kanim，目录不要再带一次后缀。
- 自制写入器注意版本、索引、UV、排序、矩阵、边界、帧率和图集留边。文件能解析不代表游戏显示正确。
- 工作、停机和故障外观要反映状态；活动部件围绕实际机械轴心运动，避免整台机器绕画布中心摇摆。
- 原生声音可以运行时引用或按自己的动画链接，核对播放与停止，不随意复制原版文件或全局改声音表。

## 占地与位置

画布尺寸、可见轮廓、动画边界和 BuildingDef 占地是不同概念。检查 KAnim 单位、controller scale、符号几何和变换共同形成的结果，不能认定每100像素必然是一格。

底座应贴合地板，注意奇偶宽度的整格/半格原点；主体和镂空合理对应占地，透明留白不能充当机器高度。非实心建筑的占地格子仍可能含空气，不要为视觉对齐把它改成实心砖。

看整个工作循环，活动部件不能穿墙或穿过相邻机器；核对端口、自动化口、翻转、小人工作位置及叠层遮挡。格子对照图有助于校准，最终位置仍看游戏表现。

### 大型交互建筑的坐标校准

Execution Platform 的 6×5 建筑开发中核对了 U59 的 `BuildingDef.GetVisualizerOffset()`：偶数宽度返回横向 +0.5 格，奇数宽度为 0。资源中心与引擎偏移分别计算，不能在图元和 controller 中各补一次半格。6 格宽的占地列相对原点为 -2 到 +3；这是当前版建筑格子约定，不是 PNG 裁剪规则。

该版本原生动画解析中的 `0.005` 几何缩放只是源码中的一个转换环节，不能据此单独推出所有资源的像素/格比例。结合图元 bounds、矩阵、controller scale 与建筑偏移核对。建筑放大后，小人仍维持原生尺寸；脚、膝、手及机械接触点单独定位，不把双方一起缩放。

## 复制人动画不是建筑动画

有跪姿、治疗姿势等需求时，先查看原生动画能否表达；确认需要新动画后，再核对 `human` 动画组、身体 symbol、头部/snap-to 元数据、前后景排序与服装覆盖。应保留当前小人的肤色、发型、衣服及太空服，不把复制人烘焙成固定角色图片。

原版动画加载与 `ModUtil.AddKAnimMod` 路径不是同一份契约；不能因原版使用 `batchgroup.yaml` 就假设标准 Mod 加载器也识别它。确认实际消费者、资源引用和缺失行为。

本项目候选方案仅针对独有 `execution_dupe_kanim`，将动画配置为 AnimOnly、引用 `human` build，并使用无原版纹理的空 build。这一接入方式仅完成源码核对与离线资源检查，尚未游戏实测，不作为通用可复制模板；私有属性设置与目标组关系均需版本核对。

进入、循环等待、退出和中断分别管理覆盖。吃饭/求生离场、取消、死亡或拆除后恢复原生动画，避免上一动作与服装覆盖残留。建筑动画与小人动画的接触时序也要在游戏中确认。原版纹理、拆包资产和本机提取目录不放入发布包。

## 动作连续性与时序

以完整动作序列为单位打磨，而非只让各片段分别能播放。先找最接近的原版动作作同场参照，核对节奏、重心、接触点和过渡；不要仅凭高帧率、很多关键帧或静态截图宣布达到原版水平。

- **接入当前姿势。** 检查进入、循环首尾、确认/取消分支、退出及原版动作交接。玩家可能在进入动作未结束或循环任意相位点击按钮，不能无条件跳到新片段固定首帧。按实际需要选择完成进入动作后接续、匹配当前相位或短过渡；等待过渡不等于延后玩家决定的生效，也不能阻碍求生抢占。
- **位置也要衔接。** 同时检查实体位置、动画根位置、工作偏移和局部姿势。原版 Worker 添加/移除工作偏移可能在开始或结束时造成整个人瞬移；姿势与运行时不能各补一次偏移。起身离台、倒地交给原版尸体等交接要对照原版起始姿势与坐标，不能只看前一段最后一帧。
- **身体有支撑。** 等待呼吸不应带着脚和接触点滑动。抬手或弯腿时保持关节连接，头部、五官、头发和装备跟随同一姿势；可用父子关节或双骨骼求解，别把各部件独立平移。插值旋转时保持刚性与镜像关系，避免直接插值矩阵造成缩瘪、翻转或肢体脱节。
- **有节奏，不只变慢。** 按动作设计预备、发力、接触、回弹和收势，给头、肩、手适量先后关系。需要平滑启停的动作可用端点速度平稳的曲线，机械撞击则可有明确顿点；别把所有部件套同一条曲线，也别为了“丝滑”抹掉原版卡通动作的力度。
- **时钟与事件一致。** 人物、机械和音效使用一致的时间基准、关键动作标记及暂停条件。模拟进度负责结果，渲染可在已提交进度内平滑呈现，不能因显示插值提前执行死亡、扣料或奖励。提高资源帧率前先核对运行时更新频率、倍速与采样方式，避免资源更密而画面仍阶梯式跳帧。
- **声音对准动作。** 将声音绑到释放、接触等实际动作点，不分别绑到按钮点击和业务结算。跨过标记时只触发一次，考虑大时间步、暂停、断电和读档，不在已越过标记后重播。原版音效自身可能有前奏、尾音或播放延迟；时间标记一致仍需听觉核对。
- **恢复而非重演。** 保存已提交阶段与进度，重建到场任务、动画覆盖后接回对应姿势；不能直接从重新跪下跳到保存的求饶或倒地帧，也不能重放奖励和声音。动画恢复、任务抢占及一次性结果的约束结合[复制人任务与效果](duplicants-chores-and-effects.md)检查。只恢复呈现，不为了动画重置业务进度。

相位变体、恢复片段和提高采样密度都是可选手段。先复用原版进入/循环/退出约定及少量过渡；需要变体时评估误差、包大小、加载与运行开销，不默认给每个动作生成全部逐帧组合，也不把某个项目的帧率、相位数量或时长当统一标准。

### U59 中容易绕过预期的路径

以下是目标版源码核对得到的提醒，换版本重新确认消费者，不直接照搬补丁：

- `Worker.StartWork` 附加 `overrideAnims` 不等于一定播放 `workAnims`；隐式播放还受 `usesMultiTool`、`animInfo.smi`、`experienceRecipient` 等条件影响。核对实际人物进入了哪个片段；必要时在到场入口显式接管，避免重复 `Play` 把本已正确的动作重置。
- `KAnimControllerBase.Queue` 会改变当前播放模式。尤其排入 `Paused` 片段可能立即暂停尚未完成的进入动作；不能只按“先播前一段，再排后一段”的直觉设计队列。核对模式切换与队列完成路径，必要时待进入动作完成后再启动受控时间轴。
- `FaceGraph.ApplyShape()` 在说话期间会让位给口型，`SpeechMonitor.Instance.DrawMouth()` 还可在渲染更新中直接写入嘴部符号覆盖。因此提高表情优先级或设置 `overrideExpression`，不一定能保证最终画面不再笑；同时核对说话、眨眼、饰品及动画自身头部的覆盖顺序。需要限制时，只限制当前目标及相关阶段，结束后恢复，不全局禁用其他小人的表情。

### 本项目案例的证据边界

Execution Platform 0.1.3 的用户截图仍有笑脸，日志确认加载了该版本；源码确认存在说话口型旁路，但截图本身没有证明它是所有笑脸的唯一原因。0.1.4 补了限定口型处理，0.1.5 补了相位衔接、关节连接、根位置过渡与恢复片段。后两版完成的是源码核对、编译、离线连续性检查及本地贴图合成，不是已获游戏验收的通用模板。

## 图标是独立显示入口

图标能显示之后，还要看尺寸、居中、辨识度和是否遮挡邻近条目。建造菜单、研究、选中面板和物品列表可能取不同资源，按适用入口检查。

菜单图独立处理图像尺寸、符号几何、UV、动画边界和偏移，不能继承建筑的地板位移。只缩小PNG可能仍然巨大。128×128是某次项目方案，不是所有Mod的硬性标准。

若生成器被多个对象共用，检查同流程对象；修图标时也留意建筑本体和其他入口有没有受影响。

## 建造阶段

分别考虑鼠标放置预览、待建蓝图、施工和成品。只添加 place/construction 名称、却复用成品图层，会显示完整填色和运行部件。

对照原版确认各阶段的动画、符号和渲染方式。需要线稿预览时单独制作外轮廓和必要结构线，不拿成品图降低透明度冒充；核对颜色、透明度和无效位置提示由谁控制，避免重复着色。施工与待建不默认相同。

这些阶段共享准确的占地、原点、缩放和地板基线，完成建造不跳位；液面、运行灯和调优标记只出现在合适阶段。

## 适量的视觉检查

按本次任务看原版同场、常用缩放、占地、图标和主要状态；涉及掉落物时看实际瓶罐/碎块。不要为局部修图强制重做全部美术。没有游戏截图时只说明资源检查结果，保留实际显示待确认。

动作改动应播放整段预览并检查接点附近的连续帧，静态姿势图不能证明衔接流畅。离线可检查接点姿势和位置差、循环接缝、关节/接触点稳定、刚性变换及声音标记；脚本阈值结合角色尺寸与动作速度设定，不只统计片段数量。

实际运行重点看早点击与不同循环相位、暂停/倍速、按设计允许的中断和恢复、退出后的原版动作交接。涉及复制人时再看普通、仿生、皮肤及太空服等相关外观，避免普通人物的离线预览通过而运行时覆盖失效。单独调用原生方法或补丁条件不等于执行了 Unity/Harmony 的完整渲染路径；无声 GIF 也不证明听感同步。缺少这些证据时明确待验证项，具体证据口径见[验证与交付](verification-and-release.md)。
